# Процесс разработки фич (PO ↔ команда)

1. **PO** описывает фичу (что нужно увидеть / как проверить).  
2. **PM** декомпозирует и **обязан делегировать** задачи sub-agents (FE/BE/QA/ARCH/…); фиксирует раздачу в `logs/` при сессии.  
3. **Агенты** реализуют / тестируют; Tech Lead собирает пакет.  
4. **PM** принимает или возвращает; при необходимости точечный hotfix с пометкой `PM direct`.  
5. **PM/команда** пересобирает и перезапускает нужные контейнеры.  
6. **PO** проверяет в UI, пишет правки.  
7. Цикл повторяется до accept.

**Правило:** исполнение через команду — не опция, а обязанность PM (см. [`product-manager.md`](product-manager.md) §3.3, [`governance.md`](governance.md) §3.1).

Текущий стенд: http://localhost:3000  
Логи сессий: `logs/`
