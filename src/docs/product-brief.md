# Product Brief — SignalDeck

## Проблема

Собрать IoT-контур «устройства → данные → дашборд → управление» обычно значит писать бэкенд, хранилище и UI с нуля либо мириться со сложным/тяжёлым UX существующих платформ.

## Решение

SignalDeck — самохостируемая платформа:

1. Устройство (или симулятор) объявляет **capabilities** (properties).
2. Сервер сохраняет схему и подбирает доступный функционал/виджеты.
3. Пользователь собирает дашборд drag-and-drop.
4. Телеметрия идёт по высоконагруженному data plane с **real-time** обновлением UI.

Ориентир: удобство Blynk, но проще и приятнее; гибкость визуализации ближе к конструкторам вроде DataLens — без их сложности на старте.

## Аудитория

| Сегмент | Роль |
|---------|------|
| Производство | целевой домен продукта (мониторинг, пилоты цехов/линий) |
| Вузы | канал внедрения и заказчиков (лаборатории, дипломы, стенды) |
| DIY / обучение | побочный сегмент на ранней стадии |

## Цели продукта

- Портфолио и дипломный проект с **production-grade** архитектурой (control vs data plane).
- Измеримый real-time ingest (не polling UI раз в секунду).
- Понятный путь от «создал устройство» до «живой график» за минуты.
- Контракт устройств, по которому позже отдельная команда пишет прошивки Arduino/ESP.

## Цели MVP

Пользователь без Postman/Swagger:

- регистрируется и входит;
- создаёт устройство и получает credentials;
- запускает симулятор (capabilities + readings);
- видит распознанные метрики;
- собирает DnD-дашборд с несколькими типами визуализаций **для одного устройства**;
- видит данные в real-time.

## Non-goals (не делаем до post-MVP)

- Реальная прошивка и автообнаружение на уровне железа (только симулятор + контракт).
- Блочная/кодовая автоматизация, уведомления, эскалации.
- Несколько устройств на одном дашборде.
- Полноценный облачный SaaS (сначала Compose / самохостинг).
- OAuth, сложные роли/org, магазин шаблонов, enterprise-админка.
- Kafka / Kubernetes «с первого дня».

## Успех MVP (accept)

- `docker compose up` поднимает систему на чистой машине.
- Симулятор стабильно кормит одно устройство.
- Capabilities влияют на доступные виджеты.
- ≥ 3 типа визуализаций в DnD-редакторе.
- Real-time без ручного refresh.
- Есть локальные замеры нагрузки (msg/s, latency publish → WS).
