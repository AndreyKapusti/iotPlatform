# QA checklist — профиль пользователя (v1)

## Окружение
- [ ] `docker compose --profile demo up -d` из `deploy/`
- [ ] UI http://localhost:3000 · login `admin` / `admin123`
- [ ] Для проверки email-конфликта: второй пользователь (register или через API)

## Навигация
- [ ] В сайдбаре виден пункт **Профиль** (рядом с Настройками)
- [ ] Клик по «Профиль» → маршрут `/profile`, active-state в сайдбаре
- [ ] Прямой переход на `/profile` (reload / bookmark) открывает форму без 404
- [ ] Без JWT → редирект на login; после входа профиль доступен

## Загрузка существующих данных
- [ ] При открытии `/profile` форма заполняется из `GET /api/v1/users/me`
- [ ] **Email** отображает текущее значение пользователя
- [ ] **Логин (username)** отображает JWT `sub` / текущий username
- [ ] Опциональные поля (ФИО, birth_date, phone, org, job_title, timezone) показывают сохранённые значения или пусто
- [ ] Аватар/инициалы: если есть имя/фамилия — буквы из них; иначе fallback (напр. из username)

## Редактирование полей
- [ ] **ФИО** — три поля: фамилия, имя, отчество; ввод кириллицы/латиницы сохраняется
- [ ] **Дата рождения** — date picker / input type=date; формат YYYY-MM-DD
- [ ] **Email** — редактируемое поле
- [ ] **Телефон** — свободный ввод (до ~32 символов)
- [ ] **Организация** — компания / кафедра
- [ ] **Должность** — job title / роль
- [ ] **Часовой пояс** — IANA (напр. `Europe/Moscow`); список или текстовое поле по реализации

## Username read-only
- [ ] Поле **Логин** disabled / read-only — нельзя изменить в UI
- [ ] Попытка отправить `username` в PATCH (DevTools) → игнор или 400; значение в БД не меняется

## Сохранение
- [ ] Заполнить/изменить поля → «Сохранить» → toast success
- [ ] Reload страницы `/profile` — все сохранённые значения на месте
- [ ] Logout → login → профиль показывает те же данные
- [ ] `GET /api/v1/users/me` после save возвращает обновлённые поля

## Пустые опциональные поля
- [ ] Очистить фамилию, имя, отчество, birth_date, phone, org, job_title, timezone → save → success
- [ ] Reload — поля пустые (null / пустая строка), форма не ломается
- [ ] Email остаётся обязательным — пустой email → ошибка валидации / 422

## Валидация: дата рождения
- [ ] Дата **в будущем** → ошибка (UI и/или 422 от API); save не проходит
- [ ] Сегодняшняя дата — допустима
- [ ] Прошедшая дата — save OK

## Email: конфликт уникальности
- [ ] Пользователь A: email `a@test.local`; пользователь B: `b@test.local`
- [ ] A меняет email на `b@test.local` → save → toast error / сообщение о занятости
- [ ] Ответ API: **409 Conflict**
- [ ] Email A в UI и БД **не** изменился после неудачного save
- [ ] Смена на **уникальный** email → save OK

## Регрессия: настройки темы
- [ ] Настройки → переключить **Тёмная** / **Светлая** — тема применяется на `/profile`
- [ ] Вернуться в Профиль — форма, карточки, кнопки читаемы в обеих темах
- [ ] Save профиля **не** сбрасывает выбранную тему (localStorage)
- [ ] Переключение темы на `/settings` после edit профиля — layout настроек без регрессии

## Негатив / auth
- [ ] PATCH `/api/v1/users/me` без Bearer → 401
- [ ] Сетевой сбой при save → toast error; форма не теряет введённые данные
