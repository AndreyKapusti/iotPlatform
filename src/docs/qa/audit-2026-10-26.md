# Аудит качества — SignalDeck

**Дата:** 2026-10-26  
**Метод:** статический разбор кода и docs. Compose и UI не запускались.  
**Ориентир:** [technical-specification.md](../technical-specification.md), [adr-001-hybrid-planes.md](../architecture/adr-001-hybrid-planes.md), [device-contract-v0.md](../device-contract-v0.md).  
**Код не менялся.**

## Вердикт

Поставка собрана по принятой архитектуре: FastAPI (control), Go (ingest, history, WebSocket), React, симулятор, Compose, Timescale. Владение устройствами и дашбордами на control проверяется. Пароли хэшируются. SQL с параметрами.

Локальный демо-путь завязан на HTTP (`USE_MQTT=false`). В этом режиме announce и telemetry в коде сходятся. Режим MQTT, который контракт считает основным транспортом, с ingest не сходится.

До сети и до следующей фазы не хватает трёх вещей: сквозной аутентификации MQTT, сверки readings со схемой устройства и любого автоматического теста. Чтение history и WebSocket без сессии — известный долг ТЗ, но в дефолтном compose эти маршруты открыты с хоста.

Находки: **4 major**, **6 minor**, **2 note**. `note` — осознанный долг или сознательный выход за MVP, не дефект приёмки.

По ним нельзя судить о типах исходников. `tsconfig.json` включает `strict`. Зависимости заново не ставились. Образ web ставит их при `npm install` в Docker.

## Находки

### AUD-01 — major — MQTT-аутентификация не сходится

**Где:** [simulator/main.py](../../simulator/main.py), [ingest/internal/mqtt/client.go](../../ingest/internal/mqtt/client.go), [deploy/mosquitto/mosquitto.conf](../../deploy/mosquitto/mosquitto.conf).

Ingest на топиках `devices/{id}/announce` и `devices/{id}/telemetry` принимает сообщение только если в JSON есть `api_key`, и сверяет его с `devices.api_key`. Симулятор в MQTT-режиме этот ключ в тело не кладёт. Он передаёт ключ как MQTT password (`username` = id устройства). Брокер этого не проверяет: `allow_anonymous true`, файла паролей и ACL нет. Клиент ingest к брокеру тоже подключается без учётных данных и пароль издателя не видит.

Итог: `USE_MQTT=true` не сохраняет announce и telemetry. Дефолт compose — `USE_MQTT=false`, HTTP с заголовком `X-API-Key` этот разрыв не задевает. Контракт при этом называет MQTT основным каналом, а HTTP — fallback. В README ingest написано, что `api_key` в JSON обязателен; симулятор этому README не следует.

**Дальше:** один способ входа. Либо брокер проверяет username/password, которые симулятор уже выставляет, и ingest доверяет брокеру. Либо ключ остаётся в JSON, и тогда его нельзя светить подписчикам `devices/#`. Анонимный брокер на опубликованном порту 1883 для этого не годится.

### AUD-02 — major — запись телеметрии не следует схеме

**Где:** [ingest/internal/store/store.go](../../ingest/internal/store/store.go) `SaveTelemetry`.

Тип точки берётся из JSON (boolean, затем number, затем string), а не из `device_capabilities`. Ключ, которого нет в схеме, всё равно пишется. Если capability объявлена как `number`, а значение пришло boolean, строка попадёт в `sensor_metrics_boolean`. History потом читает таблицу по `data_type` схемы и эту точку не покажет.

`timestamp` из payload становится и `received_at`, и `last_seen_at`. Устройство может сдвинуть «online» (FR-14) или подложить историю задним числом. Поля `metadata` и `firmware` из контракта не сохраняются.

Контракт относит политику неизвестных ключей к фазе 2. Расхождение типа и схемы — уже сейчас ломает график, это не отложенная политика.

**Дальше:** перед insert сверять имя и тип с capability; чужой тип — 4xx и без записи. `last_seen_at` ставить по часам сервера. Клиентское время, если нужно, хранить отдельно.

### AUD-03 — major — history, latest и WebSocket без владельца

**Где:** [ingest/internal/httpapi/server.go](../../ingest/internal/httpapi/server.go), [web/nginx.conf](../../web/nginx.conf), [deploy/docker-compose.yml](../../deploy/docker-compose.yml).

`GET /api/v1/telemetry/{id}/history`, `/latest` и `GET /api/v1/ws?device_id=` не проверяют JWT и не проверяют, что устройство принадлежит вызывающему. UI токен на history шлёт, ingest его игнорирует. Идентификаторы устройств — `SERIAL`, их можно перебирать.

ТЗ §4 и §7.3 прямо называют это долгом и не считают блокером приёмки. Митигация в ТЗ — не публиковать ingest наружу. Дефолтный compose публикует 8001, nginx на порту 3000 проксирует те же пути. Для localhost это терпимо. Для машины в сети — чтение чужой телеметрии без сессии.

**Дальше:** перед любым нелокальным стендом проверять сессию и `user_id` устройства (или не публиковать 8001 и закрыть эти location в nginx). Приёмку MVP это не отменяет.

### AUD-04 — major — нет тестов, линтеров и CI

В репозитории нет `*_test.go`, `test_*.py`, `*.test.ts` / `*.spec.ts`. В [web/package.json](../../web/package.json) есть Playwright и нет скрипта тестов и спек. Нет ESLint, Ruff, golangci-lint, нет `.github/workflows`.

Регрессии AUD-01 и AUD-02 сейчас ловятся только глазами. Control и ingest это как раз те места, где ошибка тихая: сообщение отбрасывается в лог или точка пишется не в ту таблицу.

**Дальше:** узкий набор тестов на отказ неверного API key, сверку типа со схемой, отказ MQTT без ключа, чужой `device_id` на control. Линтер и этот набор — в одну команду, которую можно гонять локально. CI имеет смысл следом, не вместо тестов.

### AUD-05 — minor — невалидный announce отвечает 500

**Где:** `SaveAnnounce` и `handleAnnounce`.

Пустой тип, роль или имя capability возвращают обычную ошибку. HTTP мапит любую ошибку сохранения в 500. Транзакция откатывается, процесс не падает. Критерий ТЗ §8.4 ждёт 4xx. HTTP заранее отвергает пустой список capabilities, MQTT — нет: пустой список после успешной проверки ключа стёр бы схему.

**Дальше:** ошибки контракта отличать от сбоя БД и отдавать 400.

### AUD-06 — minor — неизвестная метрика в history не 404

**Где:** `GetHistory`.

Если метрики нет в capabilities, код ищет по трём таблицам и при пустом результате возвращает пустой список без ошибки. Ветка 404 в `handleHistory` для этого случая не выполняется. Клиент видит 200 и «нет данных».

**Дальше:** неизвестную метрику отдавать 404, fallback оставить только там, где он осознанный.

### AUD-07 — minor — на Devices шесть строк только в английском

**Где:** [en.json](../../web/src/features/i18n/locales/en.json), [ru.json](../../web/src/features/i18n/locales/ru.json), [DevicesPage.tsx](../../web/src/pages/DevicesPage.tsx).

В `en` есть ключи, которых нет в `ru`: `devices.quickFilters`, `filterStale24h`, `filterNoDashboard`, `filterNoAnnounce`, `sparkline`, `newTitle`. `fallbackLng` — `ru`, поэтому русская локаль показывает имя ключа. Остальные 260 ключей совпадают.

**Дальше:** дописать эти шесть строк в `ru.json`.

### AUD-08 — minor — плавающие зависимости поставки

**Где:** [control/requirements.txt](../../control/requirements.txt), [deploy/docker-compose.yml](../../deploy/docker-compose.yml), [web/Dockerfile](../../web/Dockerfile).

Control ставит FastAPI, bcrypt и jose без версий. Образ Timescale — `timescale/timescaledb:latest-pg15`. Образ web делает `npm install`, не `npm ci`, хотя lockfile есть. У симулятора нижняя граница `requests` есть; `paho-mqtt` ставится только в Dockerfile.

Повторная сборка control и БД через месяц может уехать.

**Дальше:** зафиксировать версии control и тег Timescale. В web-образе ставить из lockfile.

### AUD-09 — minor — docs отстают от дерева `src/`

Путь `signaldeck/` остался в [documentation-standard.md](../documentation-standard.md), [ingest/README.md](../../ingest/README.md), [web/README.md](../../web/README.md), [product-manager.md](../product-manager.md) и части логов. Фактический корень поставки — `src/`.

[device-contract-v0.md](../device-contract-v0.md) описывает `POST /api/v1/receive_data/`. Код слушает `POST /api/v1/ingest/announce` и `/telemetry`. Профили симулятора `temp_humidity` и `relay_sensor` в контракте есть, в коде один зашитый набор capabilities.

[stack-decision.md](../stack-decision.md) всё ещё помечает «History API: FastAPI или Go» как открытый вопрос. History уже в Go. Redis/NATS в коде нет — это совпадает с формулировкой «фаза 2».

**Дальше:** поправить пути запуска и таблицу HTTP в контракте. Вопрос про history закрыть ссылкой на ingest.

### AUD-10 — minor — шероховатости, демо не ломают

- `GET /health` control не проверяет БД. Ingest проверяет.
- Если Mosquitto не принял соединение за 10 с, процесс ingest завершается. В compose брокер ждётся как `service_started`, не как healthy.
- [hub.go](../../ingest/internal/hub/hub.go) при полном буфере подписчика (64) событие выбрасывает молча.
- Индекс `(device_id, metric_name, received_at)` есть у numeric и нет у boolean и text, хотя history фильтрует так же.
- Уникальное имя устройства и дашборда определяется по подстроке `unique` / `duplicate` в тексте исключения.
- Симулятор печатает API key в stdout.
- JWT хранится в `localStorage`.

**Дальше:** health control с ping; retry старта MQTT без выхода процесса; лог или счётчик дропов hub. Остальное — по мере касания этих файлов.

### AUD-11 — note — демо-секреты в compose

**Где:** [docker-compose.yml](../../deploy/docker-compose.yml), Dockerfile симулятора, README.

Пароль БД, `JWT_SECRET` и демо-учётка зашиты в репозиторий. Порты Postgres 5432, MQTT 1883, control 8000 и ingest 8001 слушаются на хосте. ТЗ §7.3 прямо говорит сменить секреты перед внешней сетью. Для локального стенда это не дефект приёмки.

Ключ устройства хранится в `devices.api_key` открытым текстом и возвращается владельцу в списке устройств. Так UI показывает строку подключения. Это ожидаемо, пока ключ не уходит чужому пользователю: control режет выборку по `user_id`.

**Дальше:** перед сетью — другие секреты и bind на localhost либо reverse proxy. В отчёт значения не копировались.

### AUD-12 — note — цифровой двойник и toggle вне обязательного контура

**Где:** [HouseGardenScene.tsx](../../web/src/features/digitalTwin/components/HouseGardenScene.tsx) (около 1250 строк), [mapTwinState.ts](../../web/src/features/digitalTwin/lib/mapTwinState.ts), [widgets/index.tsx](../../web/src/components/widgets/index.tsx) `ToggleWidget`.

ТЗ не требует 3D-сцены. Сцена подбирает метрики по именам (`relay`, `реле`, …), тогда как дашборд строится от capabilities и имена не хардкодит. Toggle в UI меняет только локальный state и на брокер ничего не шлёт. FR-35 это разрешает. Симулятор подписан на `devices/{id}/command`, издателя команды в платформе нет.

**Дальше:** не считать двойник частью приёмки. Команду актуатора не обещать, пока нет publisher.

## Архитектура

Совпадает с ADR-001.

| Слой | Как в коде |
|------|------------|
| Control | FastAPI: auth, профиль, devices, capabilities, dashboards. Общая Postgres. |
| Data plane | Go: MQTT и HTTP ingest, три hypertable, WebSocket fan-out, history. |
| Брокер | Mosquitto. Анонимный, см. AUD-01. |
| UI | React, Vite, nginx проксирует control и ingest. |
| Устройство | Симулятор. По умолчанию HTTP. |

Control не пишет телеметрию. Ingest не выдаёт JWT. Общий пользователь БД у обоих сервисов — отдельной роли на чтение телеметрии нет. Для MVP приемлемо, для разнесения машин — нет.

Открытый пункт стека «Redis или NATS» не реализован. Буфер пиков — память процесса ingest (hub). При перезапуске подписчики теряют только live-хвост, история в Timescale остаётся. Retention 30–90 дней (NFR-04) политикой purge не задан; ТЗ говорит, что жёсткая политика в MVP не обязательна.

## Что в коде уже держится

- Чужое устройство и чужой дашборд на control не отдаются: выборка по `user_id`, иначе 404.
- Пароль — bcrypt. `JWT_SECRET` в настройках обязателен, значения по умолчанию в коде нет.
- Обновление профиля подставляет в SQL только поля модели, значения — параметрами.
- Announce и telemetry пишутся в транзакции. `device_id` в MQTT-топике должен совпадать с телом.
- Неверный JSON и пустые readings на HTTP — 400. Неверный ключ — 401.
- WebSocket: лимит чтения, ping, проверка Origin, если задан CORS.
- Timescale hypertable на трёх таблицах метрик.
- TypeScript в конфиге строгий. Локали ru/en совпадают, кроме AUD-07.

## Что не проверялось

- Подъём Compose, демо-логин, живой дашборд, чеклисты `docs/qa/`.
- Задержка NFR-02 и нагрузка NFR-03.
- Браузеры из NFR-06.
- Содержимое 3D-моделей.

## Порядок исправлений

1. Свести MQTT к одной проверке ключа и убрать анонимный брокер, либо явно оставить HTTP единственным транспортом MVP и не предлагать сломанный `USE_MQTT`.
2. Сверять readings со схемой; `last_seen_at` — по времени сервера.
3. Закрыть history и WebSocket сессией до любого стенда не на localhost.
4. Тесты на эти три пункта. Линтер и CI — после того, как тесты есть.
5. Версии зависимостей, шесть русских строк, 4xx на битый announce, пути `src/` в docs.
