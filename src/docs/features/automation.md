# Автоматизация и общие дашборды

Раздел «Автоматизация» содержит правила аккаунта и режимы управления. Условия обращаются к датчикам и сообщённым устройствами состояниям актуаторов. Числа поддерживают сравнения `=`, `≠`, `>`, `≥`, `<`, `≤`; строки и логические значения — `=` и `≠`. Правую часть можно задать константой или ссылкой на совместимую метрику. Сравнение чисел выполняется точно, без допуска. Группы `И` / `ИЛИ` можно вкладывать; если хотя бы один источник недоступен или устарел, всё правило ожидает свежих данных.

У правила есть ветка «то», необязательная «иначе», приоритет, срок свежести и задержка устойчивости. Новые правила включены сразу. При возврате в автоматический режим условия переоцениваются; незаданная ветка не меняет состояние. Более высокое правило блокирует нижнее для соответствующего актуатора, если его невозможно вычислить. Граф зависимостей между актуаторами проверяется при сохранении и включении; циклы запрещены.

Ручной режим аккаунта блокирует автоматику всех устройств, ручной режим устройства — его актуаторов, ручной режим актуатора — только его. Вложенные настройки сохраняются, когда верхний режим меняется обратно. При отсутствии включённого правила для актуатора он всегда доступен вручную. Пока для него есть правило и все уровни находятся в автоматическом режиме, сервер запрещает ручные команды. Переключение режима отменяет ещё ожидающие автоматические команды; устройство, уже получившее команду, может успеть её применить.

Вычисление выполняется в control после уведомления о сохранённой телеметрии и при периодической проверке. Состояния ожидания, недоступности устройства и ошибки отображаются в списке правил. При перезапуске таймер устойчивости начинается заново. Для недоступного актуатора автоматическая команда не создаётся: актуальное условие и режим повторно проверяются при следующем опросе устройства. Повторы ограничены частотой; журнал показывает намерения и результаты команд. Подтверждение от прошивки означает обработку команды и не доказывает состояние физических контактов.

## API

Все пользовательские маршруты требуют JWT; ссылки на устройства и возможности проверяются по владельцу.

- `GET /api/v1/automation/capabilities` — доступные источники и актуаторы.
- `GET`, `POST /api/v1/automation/rules` — список и создание. `PUT`, `DELETE /api/v1/automation/rules/{id}` — изменение и удаление. `PUT /api/v1/automation/rules/order` принимает `{"ids":[...]}` с полным порядком правил от высокого к низкому.
- `GET`, `PUT /api/v1/automation/modes` — настройки уровней `account`, `device`, `actuator` и список актуаторов с активными правилами. Режим: `auto` или `manual`.
- `GET /api/v1/automation/events` — последние изменения намерений и команды с результатами.
- `GET`, `POST /api/v1/shared-dashboards`, `GET`, `PUT`, `DELETE /api/v1/shared-dashboards/{id}` — общие дашборды. Каждый виджет хранит `device_id`, `metric`, `type`, `id` и `title`; все ссылки проверяются по владельцу. Старые маршруты и схема дашбордов устройств не изменены.

Пример тела правила:

```json
{
  "name": "Вентиляция",
  "enabled": true,
  "freshness_seconds": 30,
  "delay_seconds": 5,
  "definition": {
    "condition": {"op": "all", "children": [
      {"left": {"device_id": 1, "metric": "humidity"}, "operator": "gt", "right": {"kind": "literal", "value": 70}}
    ]},
    "then": [{"device_id": 2, "metric": "relay_1", "value": true}],
    "otherwise": [{"device_id": 2, "metric": "relay_1", "value": false}]
  }
}
```

Для сравнения с другой метрикой правая часть имеет вид `{"kind":"reference","device_id":2,"metric":"relay_1"}`; типы левой и правой метрик должны совпадать. Действия этой версии допускают только `boolean` + `actuator`. При изменении или удалении capability правило становится недействительным и прекращает управление.

## Проверки

`control/tests/test_automation.py` проверяет вычисления, свежесть, типы и циклы. `control/tests/integration_automation.py` запускается только при `SIGNALDECK_TEST_ISOLATED=1` и должен быть направлен переменными `TEST_CONTROL_URL` и `TEST_INGEST_URL` на изолированный стенд с тестовой базой. Он создаёт тестовых пользователей и устройства и проверяет приоритеты, задержку, иерархию режимов и общие дашборды. Реальные реле в тестах не используются.
