# ESP32 + DHT22

Прошивка для обычного ESP32 (PlatformIO `esp32dev`) считывает DHT22 на GPIO4 и цифровой PIR на GPIO25 и раз в секунду отправляет доступные показания по MQTT в SignalDeck. DHT22 опрашивается не чаще одного раза в две секунды; температура и влажность передаются только после нового опроса. Высокий уровень PIR означает движение. Если DHT22 не отвечает, состояние PIR продолжает отправляться.

Питание и уровень выхода PIR зависят от модели. Общая земля обязательна; GPIO25 ESP32 принимает сигнал не выше 3.3 V. После включения PIR может требоваться время на стабилизацию.

Подключите питание датчика к 3.3 V, землю к GND и DATA к GPIO4. Отдельному четырёхконтактному DHT22 обычно нужен подтягивающий резистор 4,7–10 кОм между DATA и 3.3 V; на трёхконтактном модуле он часто уже установлен. Распиновку проверьте по маркировке конкретного модуля.

После прошивки отправьте в COM-порт на скорости 115200 одну строку JSON с переводом строки:

```json
{"ssid":"WIFI_NAME","password":"WIFI_PASSWORD","server":"http://SERVER_LAN_IP:8001","device_id":1,"api_key":"DEVICE_API_KEY"}
```

Для настройки с компьютера скопируйте `.env.example` в `.env`, заполните поля и запустите `python configure.py --port COM4` (нужен пакет `pyserial`). Файл `.env` исключён из Git. Каждое значение записывается в одну строку; при необходимости его можно обрамить кавычками.

Используйте сеть Wi-Fi 2,4 ГГц и адрес сервера, доступный плате в сети: `localhost` для ESP32 означает саму плату. Брокер MQTT на порту 1883 должен быть доступен с ESP32; адрес берётся из SERVER_URL. Конфигурация сохраняется в энергонезависимой памяти устройства и заменяется отправкой новой строки. Не сохраняйте реальные пароли и ключи в репозитории. Локальное соединение с MQTT-брокером передаёт ключ без шифрования.

При подключении прошивка отправляет announce с возможностями `temperature`, `humidity`, `motion`, `relay_1` и `relay_2`. Сервер заменяет им существующие возможности выбранного устройства. Команды и подтверждение описаны в `../../docs/features/actuator-commands.md`. Каналы реле: GPIO26 и GPIO27; прошивка предполагает active-low входы и выключает их при запуске. Совместимость конкретного релейного модуля с управляющим сигналом 3,3 В нужно проверить до подключения нагрузки. Сообщения об ошибках Wi-Fi, сервера и датчиков выводятся в COM-порт.

Для локальной проверки показаний без SignalDeck запустите [USB-монитор](../../serial-monitor/README.md). Показания датчиков выводятся в последовательный порт отдельной задачей раз в секунду, в том числе без Wi-Fi; DHT22 обновляется раз в две секунды.
